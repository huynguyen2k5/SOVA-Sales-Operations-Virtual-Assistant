# API Contract

## Conventions

- Base path: `/api/v1`.
- JSON fields: `camelCase` at the HTTP boundary; Python and database names remain `snake_case`.
- Timestamps: ISO 8601 with UTC offset.
- IDs: UUID strings.
- Lists use stable pagination metadata.
- OpenAPI generated by FastAPI is the source of truth for the TypeScript client.
- All protected endpoints require a valid access token unless explicitly marked public.

## Error format

Use a stable problem response for expected failures:

```json
{
  "type": "https://api.example.com/problems/validation-error",
  "title": "Validation failed",
  "status": 422,
  "detail": "One or more fields are invalid.",
  "code": "VALIDATION_ERROR",
  "requestId": "6d5b2c6d-3be2-4b31-a76b-3cc4be6b22e6",
  "fieldErrors": {
    "email": ["Invalid email address"]
  }
}
```

Expected status codes:

| Status | Meaning |
| ---: | --- |
| 400 | Malformed request or unsupported file |
| 401 | Missing or expired authentication |
| 403 | Authenticated but not authorized |
| 404 | Resource not found in the User's scope |
| 409 | Duplicate or state conflict |
| 413 | File or payload too large |
| 422 | Field validation failure |
| 429 | Rate limit exceeded |
| 500 | Unexpected server failure; no internal details exposed |
| 503 | Dependency temporarily unavailable |

## API rules

- Authorization is checked in the backend for every resource query and mutation.
- Filter, sort, and pagination fields are allowlisted.
- Commit endpoints must be idempotent or reject a previously committed Import Job.
- AI generation has bounded timeout and retry behavior.
- Power BI embed configuration is short-lived and never includes client secrets.
